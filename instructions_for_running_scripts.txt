1. organize_hcp_data.py
------------------------
What it does:
  Sorts downloaded HCP Aging "Recommended" zip packages into a
  sub-<subject>/ses-<visit>/{anat,func,concat}/ folder hierarchy. Each zip
  extracts to a wrapper folder; its contents are moved as-is into the
  modality folder matching the zip type (Structural -> anat, RestFmri ->
  func, ConcatFmri -> concat). Writes a CSV manifest of what it did.

Standard command:
  python3 organize_hcp_data.py --input /path/to/zip_folder --output /path/to/organized_root

Useful flags:
  --dry-run              report what would happen, without extracting/moving anything
  --subject HCA6072156   only process zips for one subject ID


2. plot_roi_amplitudes.py
--------------------------
What it does:
  Draws interactive box plots of ROI BOLD amplitudes by visit (V1-V4), for
  the subject/visit subset listed in a group CSV file. Prompts you to pick
  which ROIs to plot after showing the list found in the data file. Saves
  each figure as both .svg and .png.

Standard command:
  python3 plot_roi_amplitudes.py --group /path/to/group5_age_gt50_at_v1_and_moca_gt21_persession.csv \
                                  --data /path/to/rfMRI_REST_FullAmplitudes.csv

Useful flags:
  -o / --output DIR   directory to save figures into (default: current directory)
  -h / --help          full usage, including CSV format requirements


3. run_fc_pipeline_v1.py
--------------------------
(Renamed 2026-07-23 from run_fc_pipeline_v2.py -- code untouched. Its
internal run-count log is still literally named analysis_log_v2.json and its
timeseries cache is still timeseries_<session>.csv -- neither string was
updated when the file was renamed.)

What it does:
  Interactive single-subject/session functional connectivity pipeline.
  Prompts for the raw data root, then shows subjects/sessions as colored
  tiles (red->green = how many times each has been analysed before,
  tracked in Analysed_data/analysis_log_v2.json). Parcellates the
  grayordinate dtseries into 400 Schaefer cortical + 16 Tian-S1 subcortical
  parcels (incl. hippocampus) via wb_command -cifti-parcellate
  (Groups A/B), probability-weighted-extracts 5 CIT168 midbrain nuclei
  (SNc, SNr, VTA, PBP, red nucleus -- Group C) and mask-mean-extracts 6
  HCPex basal forebrain structures (mammillary bodies, septal nucleus,
  nucleus basalis -- Group D) from the volumetric BOLD -- 427 parcels
  total. Group B, C, and D all read the one volumetric BOLD file with the
  same mask-mean method; only Group A (cortex) stays on the
  CIFTI/grayordinate + MSMAll path, since surface-registration precision is
  the actual reason to prefer it there. Lets you pick any subset across the
  four atlas groups (shown as cards, e.g. 'B1, C3, D5-6') before computing
  the Pearson + Fisher-z FC matrix and a labeled heatmap. Group A's atlas
  card shows a human-readable label per parcel (e.g. "A107 L SalVentAttn
  Medial #1") -- display only, extraction/region_names.txt/matrix axis
  labels still use the raw Schaefer name.

  After picking a subject/session and which parcels to include in the
  "standard" matrix, NO mode menu -- every run always computes the same
  fixed five analyses (four of five have no choice to make anyway):
    - standard      -- FC matrix over whichever parcels you picked
    - graph_vta      -- fixed VTA + NbM(L) + NbM(R) + HC(L) + HC(R) graph,
                         5 nodes, left/right kept separate
    - graph_sn       -- fixed SNc + SNr + NbM(L) + NbM(R) + HC(L) + HC(R)
                         graph, 6 nodes, left/right kept separate
    - triangle_vta   -- same nodes as graph_vta, but left/right pairs
                         averaged first -> plain 3-node triangle (NbM, VTA, Hippocampus)
    - triangle_sn    -- same idea for SN (SNc+SNr averaged into one "SN"
                         node) -> plain 3-node triangle (NbM, SN, Hippocampus)
  graph_vta/graph_sn render as a node-link graph (region name only, no
  atlas/source text) instead of the square heatmap: each edge shows its
  Pearson r, colored + thickness-scaled on the same red/blue diverging scale
  as the heatmap. triangle_vta/triangle_sn use the same graph style, just
  with the combined 3-node set.

Standard command:
  python3 run_fc_pipeline_v1.py

Output:
  Analysed_data/<subject>/<session>/func/
    fc_matrix_corr_<mode>.csv, fc_matrix_fisherz_<mode>.csv,
    region_names_<mode>.txt, fc_matrix_<mode>.png / .svg
    for mode in {standard, graph_vta, graph_sn, triangle_vta, triangle_sn}
  All five save directly into that one func/ subfolder (no per-mode
  subfolder within it) as plain CSV (not .npy), filename suffixed by
  which analysis produced it so nothing collides. Full 427-parcel
  timeseries cached per-subject at
  Analysed_data/<subject>/timeseries_<session>.csv (plain CSV; delete to
  force a fresh extraction). Run-count log: analysis_log_v2.json.

Requires:
  Atlas files under <raw root>/atlases/ (or the /Volumes/njainmpi/... fallback):
  schaefer400_tianS1.dlabel.nii, CIT168_prob_func2mm.nii.gz, CIT168_labels.txt,
  HCPex_2mm.nii, HCPex_basal_forebrain_labels.txt, Tian_Subcortex_S1_3T.nii,
  Tian_Subcortex_S1_labels.txt (the official volumetric Tian-S1 atlas,
  verified on the same 91x109x91 @ 2mm grid as CIT168/HCPex).


4. run_fc_pipeline_v2.py
--------------------------
(Renamed 2026-07-23 from run_fc_pipeline_v3.py -- code untouched. Its
internal run-count log is still literally named analysis_log_v3.json and its
timeseries cache is still timeseries_hcpex_<session>.csv -- neither string
was updated when the file was renamed.)

What it does:
  Interactive single-subject/session functional connectivity pipeline,
  HCPex-only. Unlike run_fc_pipeline_v1.py (four atlas groups, 427
  parcels), this version sources every parcel -- cortex included -- from
  one atlas: HCPex (Huang & Rolls et al. 2022), 426 regions total (360
  HCP-MMP1.0 cortex + 66 subcortical/midbrain/basal-forebrain: thalamic
  nuclei, striatum, amygdala, SNpc/SNpr/VTA, mammillary bodies, septal
  nucleus, nucleus basalis, hippocampus). One file, one extraction method
  (volumetric mask-mean via the deterministic HCPex_2mm.nii label volume)
  for every region -- the tradeoff is losing MSMAll surface-registration
  precision for cortex, which v1 got by keeping cortex on the
  CIFTI/grayordinate path.

  Prompts for the raw data root, subject, and session (colored tiles as in
  v1, tracked in its own analysis_log_v3.json), then which parcels to
  include in the "standard" FC matrix. Every run always computes all five
  analyses for that session:
    - standard      -- FC matrix over whichever parcels you picked
    - graph_vta      -- fixed NbM <-> VTA <-> Hippocampus graph, left/right kept separate
    - graph_sn       -- fixed NbM <-> SN <-> Hippocampus graph, left/right kept separate
    - triangle_vta   -- same 3 regions as graph_vta, but left/right pairs
                         averaged first, giving a plain 3-node triangle
    - triangle_sn    -- same idea for SN (SNpc+SNpr averaged into one "SN" node)
  Left/right are kept separate for the graph_* modes because HCPex
  lateralizes VTA and SNpc/SNpr (unlike CIT168, which v1 used).

Standard command:
  python3 run_fc_pipeline_v2.py

Output:
  Analysed_data/<subject>/<session>/func/
    fc_matrix_corr_<mode>_hcpex.csv, fc_matrix_fisherz_<mode>_hcpex.csv,
    region_names_<mode>_hcpex.txt, fc_matrix_<mode>_hcpex.png / .svg
    for mode in {standard, graph_vta, graph_sn, triangle_vta, triangle_sn}
  All saved as plain CSV (not .npy), suffixed "_hcpex", into their own func/
  subfolder -- mirroring the anat/ subfolder cross_sectional_analysis_v2.py
  uses for its outputs.
  Full 426-parcel timeseries cached per-subject at
  Analysed_data/<subject>/timeseries_hcpex_<session>.csv (delete to force a
  fresh extraction, e.g. after updating the atlas file).

Requires:
  Atlas files under <raw root>/atlases/ (or the /Volumes/njainmpi/... fallback):
  HCPex_2mm.nii, HCPex_LookUpTable.txt (full descriptive parcel names -- not
  the short-code HCPex_basal_forebrain_labels.txt that run_fc_pipeline_v1.py's
  Group D uses).


5. run_fc_pipeline_batch_v2.py
---------------------------------
(Rebuilt from scratch 2026-07-23. This filename previously referred to a
different script -- the batch counterpart of the old CIT168/Tian-S1
pipeline now called v1. That version is gone; this is a new, unrelated
script batching the CURRENT run_fc_pipeline_v2.py, the HCPex-only
pipeline.)

What it does:
  Non-interactive batch driver for run_fc_pipeline_v2.py. Imports that
  script as a module and reuses its extraction/analysis/plotting/logging
  functions unchanged -- only the interactive subject/session/parcel
  pickers are replaced with a loop over every sub-*/ses-* session found
  under a raw data root. Runs the same fixed five analyses (standard,
  graph_vta, graph_sn, triangle_vta, triangle_sn) per session. The
  "standard" matrix's parcel selection is made ONCE up front (same syntax
  as the interactive card picker -- 'all', a bare group letter, or
  labels/ranges like 'A1, B2, B4' / 'A1-10') and applied identically to
  every session, since HCPex's 426 parcel names/order are fixed by the
  atlas, not subject-specific. Sessions that already have a standard FC
  matrix are skipped unless --force. Per-session timeseries caching
  (Analysed_data/<subject>/timeseries_hcpex_<session>.csv) works exactly as
  in the interactive script. Each session is wrapped in its own
  try/except so one failure doesn't abort the batch; a
  done/skipped/missing/failed summary prints at the end.

Standard command:
  python3 run_fc_pipeline_batch_v2.py /path/to/Raw_Data

Useful flags:
  (raw_data_root omitted)   falls back to the same interactive
                             tab-completing path prompt as run_fc_pipeline_v2.py
  --force                   re-run sessions that already have
                             fc_matrix_corr_standard_hcpex.csv
  --subjects sub-A,sub-B    restrict to specific subject folder names
  --parcels all             parcel selection for the "standard" matrix
                             (default 'all'; same syntax as the interactive
                             card picker)

Output (per session, see run_fc_pipeline_v2.py):
  Analysed_data/<subject>/<session>/func/
    fc_matrix_corr_<mode>_hcpex.csv, fc_matrix_fisherz_<mode>_hcpex.csv,
    region_names_<mode>_hcpex.txt, fc_matrix_<mode>_hcpex.png / .svg
    for mode in {standard, graph_vta, graph_sn, triangle_vta, triangle_sn}
  Shares analysis_log_v3.json with run_fc_pipeline_v2.py, so a session
  processed here shows up already-analysed if you later open the
  interactive tool on it.

Requires:
  Same atlas files as run_fc_pipeline_v2.py.

Caution:
  This dataset currently has 73 sessions. Know the real scope before
  launching a "quick test" -- check `find Raw_Data -name "ses-*" | wc -l`
  first, or use --subjects to restrict to a couple of subjects, since
  letting it run against every session is very different from a smoke test.


6. cross_sectional_analysis_v1.py
------------------------------------
(Renamed 2026-07-23 from cross_sectional_analysis.py -- code untouched.)

What it does:
  Interactive cross-sectional anatomical analysis pipeline. Prompts for the
  raw data root, subject, and session (colored tiles, same UI as
  run_fc_pipeline_v2.py, tracked in its own analysis_log_anat.json), then
  for that session extracts:
    - Cortical thickness (corrThickness_MSMAll) and myelin (MyelinMap_BC_MSMAll),
      both parcellated to Schaefer-400 cortex by matching (structure, vertex
      index) between schaefer400_tianS1.dlabel.nii and the dscalar in pure
      Python/nibabel -- verified to match wb_command -cifti-parcellate to
      ~1e-8, without needing wb_command or a cortex-only atlas file.
    - Subcortical/regional volumes from wmparc.nii.gz -- every FreeSurfer
      label present, voxel count x voxel volume (read from the file's own
      affine; this dataset's wmparc is 0.8mm iso = 0.512 mm^3/voxel, not the
      2mm functional grid the FC pipeline uses). Labels named via
      FreeSurferColorLUT.txt ($FREESURFER_HOME, or /Applications/freesurfer/
      8.1.0/ as fallback) -- no atlas needed, wmparc is already FreeSurfer's
      atlas-labeled segmentation.

Standard command:
  python3 cross_sectional_analysis_v1.py

Output:
  Analysed_data/<subject>/<session>/anat/
    cortical_thickness_schaefer400.csv, myelin_schaefer400.csv,
    subcortical_volumes_wmparc.csv, subcortical_volumes_key_structures.png,
    cortical_thickness_myelin_summary.png, manifest.txt (source files +
    atlas/LUT used, for provenance)
  Own run-count log: Analysed_data/analysis_log_anat.json.

Requires:
  schaefer400_tianS1.dlabel.nii under <raw root>/atlases/ (already present
  from run_fc_pipeline_v1.py). FreeSurferColorLUT.txt via $FREESURFER_HOME or
  /Applications/freesurfer/8.1.0/.

Note:
  No aseg.stats (or equivalent eTIV source) was found anywhere in this
  dataset's structural output -- subcortical_volumes_wmparc.csv reports raw
  mm^3, not head-size-normalized.


7. cross_sectional_analysis_v2.py
--------------------------------------
What it does:
  Same as cross_sectional_analysis_v1.py (cortical thickness + myelin on
  Schaefer-400; wmparc regional volumes), PLUS volumes for three structures
  FreeSurfer doesn't segment at all -- VTA, Substantia Nigra (SNc/SNr), and
  Nucleus Basalis -- pulled from HCPex_2mm.nii instead (the same atlas
  run_fc_pipeline_v2.py uses for these regions). wmparc/FreeSurfer stays
  authoritative for everything it already covers (spot-checked: HCPex's own
  Hippocampus label reads ~half of wmparc's, confirming wmparc is the better
  source where both exist).

  Computed two ways, both saved side by side, because HCPex is a fixed
  template atlas in standard MNI152 space -- counting voxels there directly
  gives every subject the identical volume (zero variance, useless for
  cross-sectional comparison):
    - standard-space volume -- raw voxel count in HCPex_2mm.nii (2mm voxels).
      Same for every subject by construction; reference number only.
    - native-space volume   -- HCPex_2mm.nii warped into this subject's own
      T1w/acpc space via FSL applywarp, using their own inverse nonlinear
      warp field (MNINonLinear/xfms/standard2acpc_dc.nii.gz), nearest-
      neighbor interpolation, then counted at native voxel size (0.512 mm^3
      on this dataset). This is the one that actually varies by subject --
      the correct value for cross-sectional comparison.

Standard command:
  python3 cross_sectional_analysis_v2.py

Output:
  Analysed_data/<subject>/<session>/anat/
    cortical_thickness_schaefer400.csv, myelin_schaefer400.csv,
    subcortical_volumes_wmparc.csv, midbrain_basalforebrain_volumes_hcpex.csv
      (region, label_id, standard_voxel_count, standard_volume_mm3,
       native_voxel_count, native_volume_mm3),
    subcortical_volumes_key_structures.png,
    midbrain_basalforebrain_volumes_hcpex.png,
    cortical_thickness_myelin_summary.png, manifest.txt
  Own run-count log: Analysed_data/analysis_log_anat_v2.json (separate from
  v1's analysis_log_anat.json).

Requires:
  Everything cross_sectional_analysis_v1.py requires, plus HCPex_2mm.nii +
  HCPex_LookUpTable.txt under <raw root>/atlases/ (already present from
  run_fc_pipeline_v2.py), and FSL's applywarp on PATH.

Note:
  Same eTIV caveat as v1 -- all volumes reported are raw mm^3.


8. cross_sectional_analysis_batch_v2.py
------------------------------------------
(New 2026-07-23 -- did not exist before.)

What it does:
  Non-interactive batch driver for cross_sectional_analysis_v2.py. Imports
  that script as a module and reuses its extraction/plotting/logging
  functions unchanged -- only the interactive subject/session picker and
  single-session main() are replaced with a loop over every sub-*/ses-*
  session found under a raw data root, per-session error isolation (one
  bad session doesn't abort the batch), and a skip-if-already-done check.
  Work that's identical for every subject (FreeSurfer/HCPex LUTs, the
  cortex vertex LUT, and the HCPex standard-space volumes -- fixed by
  construction, same for every subject) is computed once up front instead
  of per session. Sessions that already have anat/manifest.txt are skipped
  unless --force.

Standard command:
  python3 cross_sectional_analysis_batch_v2.py /path/to/Raw_Data

Useful flags:
  (raw_data_root omitted)   falls back to the same interactive
                             tab-completing path prompt as
                             cross_sectional_analysis_v2.py
  --force                   re-run sessions that already have anat/manifest.txt
  --subjects sub-A,sub-B    restrict to specific subject folder names

Output (per session, see cross_sectional_analysis_v2.py):
  Analysed_data/<subject>/<session>/anat/
    cortical_thickness_schaefer400.csv, myelin_schaefer400.csv,
    subcortical_volumes_wmparc.csv, midbrain_basalforebrain_volumes_hcpex.csv,
    subcortical_volumes_key_structures.png,
    midbrain_basalforebrain_volumes_hcpex.png,
    cortical_thickness_myelin_summary.png, manifest.txt
  Shares analysis_log_anat_v2.json with cross_sectional_analysis_v2.py.

Requires:
  Same atlas files + FSL applywarp as cross_sectional_analysis_v2.py.
